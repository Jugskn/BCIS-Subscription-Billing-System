# Decisions

## 2026-10-07 — Reports, dashboard, print exports

- Shared export helper (`apps/api/src/lib/export.ts`): ExcelJS XLSX, pdfmake PDF, CSV; money formatted to pesos only at output; PDF header (BCIS, title, filters, generated by, datetime), right-aligned amounts, totals row, page numbers.
- Preview routes require `report.view`; export routes require `report.export` (audit export also needs `audit.view`). Dashboard/receivables aging use `receivable.view` and share `receivables-service` aggregations with report AR aging so totals match.
- Collector remittance/shortage: until collection batches exist, remitted = collected by assigned collector and shortage/overage is 0 (documented on report rows).
- Print: Receipt, SOA, Route Sheet are shell-free routes with `window.print()` + Tailwind `print:` utilities.

## 2026-10-07 — CORS for Electron + Vite

- `@fastify/cors` methods must list PUT/PATCH/DELETE/OPTIONS (v11 default is GET/HEAD/POST only).
- Allowed origins from `CORS_ORIGINS` (comma-separated); default Vite `localhost`/`127.0.0.1:5173` plus packaged Electron `file://` / opaque `null`. Never `origin: "*"` with credentials.
- CORS hook `onRequest` so OPTIONS preflight skips auth/permission preHandlers.
- Renderer and Electron main use `http://127.0.0.1:3001` only (not localhost) for the API base URL.

## 2026-10-07 — Options endpoints and async combobox

- List endpoints keep `pageSize` max 100; entity pickers use non-paginated options routes capped at 50 with optional `?search=`.
- Paths: `/subscribers/options` (ACTIVE/INACTIVE), `/plans/options`, `/areas/options`, `/collectors/options` (active users with Collector role).
- Added RBAC role `Collector` (subscriber.view + receivable.view) for field staff assigned to subscribers/areas.
- Desktop: one `AsyncCombobox` (debounced search; "No results" only on empty success; API errors surfaced). Toast on successful area/plan/subscriber edits.

## 2026-10-07 — Validation errors and collection areas

- `VALIDATION_ERROR` responses always include `issues: [{ field, message }]` (friendly top-level message kept); Pino warn-logs the same issues (passwords already redacted).
- Optional free-text fields (area description): empty string treated as null in Zod, stored as `""` in NOT NULL columns.
- Collection areas: edit via PUT; delete only when no subscribers reference the area.

## 2026-10-07 — Foundation stack and auth

- Monorepo: `apps/api`, `apps/desktop`, `packages/shared`, `packages/db` per project rules.
- Auth: JWT bearer tokens with `session_version` on `users`; logout increments version (revokes outstanding tokens).
- Lockout: failed attempt counter + `locked_until`; defaults 5 attempts / 15 minutes (overridable via env).
- `audit_logs`: insert-only enforced by DB triggers blocking UPDATE/DELETE.
- Desktop: `contextIsolation=true`, `nodeIntegration=false`; preload exposes config + lock/logout helpers only.
- Role matrix aligned to SPEC 3.1 minimums: Administrator is operational (no user/role/settings/audit/backup); Cashier includes `gcash.verify`; Technician is service-scoped only. Seed replaces `role_permissions` per role so removals apply on re-seed.
- Sidebar follows SPEC 4.3b nested sections; placeholder child routes until domain screens land.

## 2026-10-07 — Subscribers, plans, service accounts

- Account numbers: locked `account_sequences` table (`SUB-`, `SVC-` prefixes, 6-digit zero-padded).
- Money on plans/accounts stored as bigint centavos; `service_accounts.current_rate_centavos` snapshotted at creation; plan price updates never backfill existing accounts.
- Subscriber search: `pg_trgm` GIN indexes + `/subscribers/search` endpoint (invoice/receipt/GCash hooks deferred).
- Status history: `service_events` for every service account status change; subscriber status changes go to `audit_logs`.
- No hard-delete on subscribers; terminal statuses require `subscriber.deactivate`.

## 2026-10-07 — Payments, allocation, GCash, receipts

- Pure allocation in `packages/shared/src/billing/allocation.ts` (oldest-first + manual); Vitest AT-01..04 first.
- Migration `0003_payments`: `payments` (methods, statuses, unique `idempotency_key`, `unallocated_centavos`), `payment_allocations`, `payment_proofs`, `payment_reversals`, `receipts` (`RCPT-` from locked `account_sequences`); partial unique on GCash `reference_number` among PENDING/VERIFIED; ledger type `PAYMENT_REVERSAL`.
- Post payment: one transaction — lock open invoices FOR UPDATE, allocate, insert payment + allocations + ledger credit + receipt + audit, update invoice statuses; leftover → `subscriber_credits`. Idempotent replay on same key.
- GCash: multipart proof (jpg/png/pdf, size limit, safe filename) → PENDING only; verify posts as VERIFIED; reject frees reference; duplicate ref → 409.
- Reversal: linked row, offsetting ledger debit, restore invoice paid/balance/status, receipt VOID (number reserved), reason + audit required.
- UI: Receive Payment, Payment History (permission-gated reverse dialog), GCash two-pane queue, receipt print layout; Cashier gains `gcash.reject`.

## 2026-10-07 — Billing, invoices, ledger

- Pure billing domain in `packages/shared/src/billing/` (period, invoice totals/credit/overdue, ledger running balance) with Vitest tests first.
- Migration `0002_billing`: `billing_cycles`, `invoices` (partial unique on `service_account_id` + `billing_period` where status ≠ VOID), `invoice_items` (rate snapshot), `adjustments`, `ledger_entries` (append-only), `subscriber_credits` (unapplied per subscriber).
- Generator: one invoice per ACTIVE account with `billing_start <= period`; due date from account due day; auto-applies `subscriber_credits`; posts invoice debit + credit-application ledger rows; idempotent skip when non-VOID invoice exists (AT-11).
- Void/adjust: reason required, audited, offsetting ledger entries; void restores applied credit to subscriber.
- Overdue derived at read time: `today > due_date + grace_days` from `application_settings`.
- Ledger list uses domain `computeRunningBalances`; SOA endpoint adds opening/closing balance for date range.
- UI: Billing > Current / Generate / Invoices; Subscriber Profile Billing and Ledger tabs.
